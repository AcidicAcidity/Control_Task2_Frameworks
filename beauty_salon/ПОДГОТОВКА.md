# Шпаргалка по защите (27 критериев)

Запуск: `pip install django` → `python create_db.py` (пересоздать БД) → `python manage.py check` → `python manage.py runserver` → http://127.0.0.1:8000/
Цепочка: SQLite → SQL (beauty/db.py) → sqlite3 → view → context → шаблон → HTML/CSS/JS

## Критерии
1. Запуск: `check` без ошибок; settings.py (INSTALLED_APPS, TEMPLATES, STATICFILES_DIRS, DB_PATH), beauty_salon/urls.py (include трёх приложений). Сценарий: / → /cabinets/ → /beauty/ → ?clients=2 → клик по визиту → «Назад к списку».
2. SQLite: sql/init.sql (таблицы cabinets и beauty, 4 кабинета, 9 визитов, FK cabin_id); beauty/db.py: sqlite3.connect, execute().
3. Главная: homepage/views.py home() → context {"visits"} → home.html (название, описание, навигация из base.html).
4. Количество: db.get_visits() → SELECT ... FROM beauty; в шаблоне `{{ visits|length }}`. Покажи INSERT/DELETE и обновление страницы.
5. Навигация: имена маршрутов `homepage:home`, `cabinets:cabinet_list`, `beauty:visit_list`, `beauty:statistics`; в base.html и home.html `{% url %}`.
6. Список: beauty/views.py visit_list() → db.get_visits() → VISITS_SQL (SELECT) → conn.execute → context["visits"].
7. Данные визита: visit_card.html выводит title, service_type, visit_date, duration, clients, status; цикл `{% for %}` в visit_list.html.
8. Кабинет: `LEFT JOIN cabinets c ON c.id = v.cabin_id` в VISITS_SQL (LEFT — чтобы визит без кабинета не пропал); поля cabin_name, cabin_capacity, cabin_profile.
9. Карточка: `{% include "beauty/includes/visit_card.html" %}` внутри for в visit_list.html.
10. Пусто: `{% empty %}` в visit_list.html. Демонстрация: ?clients=99 или пустая таблица.
11. Фильтр: `request.GET.get("clients")` → `_positive_int()` → get_visits(min_clients). Сравни ?clients=1 (9 шт.) и ?clients=3 (2 шт.).
12. Параметризация: `WHERE v.clients >= ?` и `conn.execute(sql, params)` — значение отдельно от SQL.
13. Нет результатов: сообщение «По вашему запросу визитов не найдено…» (?clients=99). Некорректный ввод (?clients=abc) → предупреждение, фильтр не применяется.
14. ORDER BY / LIMIT: словарь SORT_OPTIONS (белый список), `sort not in SORT_OPTIONS → DEFAULT_SORT`; LIMIT `?`. Пример: ?sort=clients_desc&limit=3. Подстановка в SQL — только значение из словаря, не ввод пользователя.
15. Slug: beauty/urls.py `path("<slug:slug>/", views.visit_detail, name="visit_detail")`; view → db.get_visit_by_slug(slug) (`WHERE v.slug = ?`).
16. Детали: visit_detail.html — все поля + кабинет/вместимость/тип кабинета (одним JOIN-запросом).
17. Переход: `{% url 'beauty:visit_detail' slug=visit.slug %}` в visit_card.html.
18. 404: `if visit is None: return render(request, "404.html", status=404)`; открой /beauty/nope/. (render со статусом, а не Http404 — т.к. при DEBUG=True Django показал бы техническую страницу.)
19. Ошибка БД: db.execute ловит sqlite3.Error → кидает DatabaseError; каждый view ловит его и рендерит error.html со статусом 500, без деталей. Демонстрация: переименовать beauty.db.
20. Общий шаблон: base.html с `{% block title %}` и `{% block content %}`; все страницы — `{% extends "base.html" %}`.
21. `{% if visit.status == "запланирован" %}Клиент записан{% elif ... "обслуживается" %}Идёт обслуживание{% elif ... "завершён" %}Услуга оказана`; плюс цветная рамка карточки через CSS-класс.
22. Фильтры: `date:"d.m.Y H:i"`, `default:"Кабинет не указан"`, `length`, `upper`, `truncatechars:30` (длинное название «Окрашивание в технике балаяж…» обрезается), `slugify`. Дата: в db._prepare строка превращается в datetime — иначе date не работает.
23. Статистика: SELECT service_type, COUNT(*), SUM(clients) FROM beauty GROUP BY service_type HAVING COUNT(*) >= ? → get_statistics → statistics view → statistics.html. По умолчанию min=3: стрижка 4, маникюр 3 (окрашивание 2 — отсеяно HAVING). ?min=2 — появится окрашивание.
24. Изменение данных: UPDATE/INSERT в sqlite3 → F5, значения меняются; шаблоны не трогаем, т.к. каждый запрос идёт в БД заново.
25. Полный путь: возьми фильтр ?clients=2: GET → request.GET → views.visit_list → db.get_visits → execute → context → visit_list.html → HTML.
26. CSS/логотип: `{% load static %}` + `{% static 'css/style.css' %}`, `{% static 'img/logo.png' %}` в base.html. Покажи правила .visit-card, .nav, .empty-message.
27. JS: `<script src="{% static 'js/main.js' %}">` в base.html; кнопка «Подробнее» (.toggle-details) показывает/скрывает блок .details (hidden-атрибут).

## Вопросы, которые могут задать
- Почему нельзя f-строкой? SQL-инъекция; параметры `?` экранируются драйвером.
- Почему order_by всё же в строке? Имя поля/направление нельзя параметризовать — поэтому белый список.
- Почему statistics раньше slug? Иначе /beauty/statistics/ совпадёт с `<slug:slug>`.
- Чем WHERE отличается от HAVING? WHERE фильтрует строки до группировки, HAVING — группы после.
- Почему DATABASES = {}? ORM не используется.
- Почему conn.close() в finally? Чтобы соединение закрывалось даже при ошибке.
- Что делает LEFT JOIN vs INNER? LEFT сохраняет визит без кабинета (cabin_id NULL → default «Кабинет не указан»).
- Где view-функции передают данные? Третий аргумент render() — context.
